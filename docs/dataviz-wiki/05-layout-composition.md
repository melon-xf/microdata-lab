# 05 — Layout & Composition

Sources: Cairo ch. 7 [C], Knaflic ch. 3, 5 [K], Schwabish ch. 3, 12
[S].

## Structure before skin

"The structure is the skeleton and muscles of your graphic; the visual
style is the skin" [C pp. 136–137]. Decide the information hierarchy
first; styling follows.

**The rectangles method** [C pp. 152–153]: before designing anything,
sketch the page as labeled rectangles (title, lede, chart, key,
footnote). If the rectangles don't read in a logical order, the chart
won't either. Applies one level down too — inside the chart, the
title/key/axis blocks form their own rectangles.

## Reading path

- Western readers: z-pattern from top-left, 2–3 saccades/sec
  [C pp. 92–93; K doc 11].
- Top of page = precious real estate; most important content first
  [K doc 12].
- "How to read" elements (title, axis titles, key) in the upper-left
  so they're hit before the data [K doc 11, 14].
- One element leads to the next; never make the reader reverse
  direction to understand [C p. 152].

## White space

- "Never add data just for the sake of adding data" [K doc 11].
- White space = pauses in public speaking [K doc 11]; margins stay free
  of text and visuals; don't stretch charts to fill space.
- Closure principle: enclosing boxes and background panels are
  unnecessary — eyes complete the shape; white space separates instead
  [K doc 11; C pp. 104–105].
- One important thing = the only thing on the page [K doc 11].

## Alignment

- Clean horizontal AND vertical lines; left-justify text (no ragged
  center blocks) [K doc 11].
- Aligned to a shared grid: title, chart body, source line share left
  edge; annotations align to the marks they describe.
- Deliberate, not happenstance: "don't let your design choices be
  happenstance" [K doc 12].

## Layering (the onion)

Summary/headline layer as entry point; deeper layers below; logical
navigation order [C pp. 78–79]. A chart answers one question and
invites the next.

## Small multiples

- Identical axis min/max across panels — non-negotiable [K doc 17;
  S pp. 148–149].
- Order panels alphabetically or by value; label each panel; shared
  axis chrome only once.
- Vertical stacking: trend-per-category reading; horizontal:
  cross-category comparison [K doc 17].

## Aspect ratio

- Bank-to-45° heuristic for line slopes; avoid extreme aspect that
  manufactures drama or hides change [S pp. 139–140 for y-range].
- Mobile-first consideration: test at phone width; horizontal-space
  forms degrade first [S pp. 72–73].

## Grids & axes chrome

- Remove chart border; gridlines thin light gray or gone (declutter
  order: border → gridlines → markers → label cleanup → direct labels
  → consistent color) [K doc 11].
- Axis lines gray, not black; data ink darker than chrome ink
  [K doc 14].

## Renderer checklist

- [ ] Rectangle test: title/lede/chart/source share a left grid line
- [ ] No enclosing boxes or background panels
- [ ] Gridlines absent or light-gray and behind the data
- [ ] Small multiples: shared scales verified
- [ ] Reading order top-left → bottom-right matches the claim's logic
- [ ] Chart sized to content, not to the container
